# Critter Overlay: v1.7 and v1.8 Developer Handoff

This document is the implementation plan for the next two releases. It is written to be self-contained: a developer or coding agent should be able to start work from this file plus the v1.6 source tree.

The plan is deliberately scoped down. v1.7 ships an installer and nothing else. v1.8 ships offline custom critters and nothing else. AI animation, payment flows, drawing canvases, and movement personality presets are all explicitly deferred. The intent is two small, low-risk releases rather than one ambitious one.

---

## 1. Recommended release split

### v1.7: Installer release

In scope:
- PyInstaller `--onedir` build pipeline with checked-in `.spec` file
- Inno Setup installer with in-place upgrade support
- Bundled Python interpreter and all dependencies (no external Python required)
- Preservation of `%APPDATA%\CritterOverlay\` across install, upgrade, and uninstall
- Clean-VM tested on Windows 10 and Windows 11
- Optional pre-generation of sound WAVs at build time to drop runtime numpy dependency, only if it lands inside the v1.7 timeline

Out of scope:
- Any new feature
- Custom critters (groundwork only: empty `custom\` folder created by installer if missing)
- Code signing (document the SmartScreen warning, do not solve it yet)
- Auto-update from inside the app

### v1.8: Offline custom critters

In scope:
- Custom critter folder structure under `%APPDATA%\CritterOverlay\custom\`
- Import pipeline for transparent PNG, JPG (with background removal), and animated GIF
- Procedural 4-frame animation for static images (squash, stretch, lean, mild rotation)
- `CustomAnimal` class inheriting from `Animal`
- Per-pixel alpha-mask hit detection for custom critters
- Sound preset assignment with deterministic per-critter variation
- Auto-extracted dominant-colour palette stored in metadata, but trail off by default
- Settings UI: new Custom tab with create, enable, weight, sound preset, test spawn, delete

Out of scope (deferred to v1.9 or later):
- AI animation of any kind
- In-app drawing canvas
- Per-critter trail style picker
- Movement personality presets (hop, perimeter, erratic)
- Backend, payments, license tokens
- Custom-critter-specific rare variants

### v1.9 and beyond

Candidates, prioritised by likely value relative to cost:
1. Movement personality presets (parameters already exist in code, low cost)
2. In-app drawing canvas using pygame surface, with basic brush, eraser, fill, colour picker
3. Per-critter trail style and palette UI
4. Optional AI img2img enhancement of procedural frames using a local model, only if there is real demand
5. Code signing if distribution widens
6. Custom critter sharing via export/import bundle (zip of the critter folder)

## 2. Installer implementation plan

### Build structure

Add to repo root:
- `CritterOverlay.spec` (PyInstaller spec, checked in)
- `installer/installer.iss` (Inno Setup script, checked in)
- `installer/icon.ico` (app icon, checked in)
- `installer/license.txt` (optional, if you want a license screen in the wizard)
- `build.ps1` (PowerShell script that runs PyInstaller then Inno Setup compiler)
- `.gitignore` entries for `build/`, `dist/`, `installer/output/`

Build flow:
1. `build.ps1` cleans `build/` and `dist/`
2. Runs `pyinstaller CritterOverlay.spec`
3. Verifies `dist/CritterOverlay/CritterOverlay.exe` exists and launches successfully (smoke test)
4. Runs Inno Setup compiler on `installer/installer.iss`
5. Outputs `installer/output/CritterOverlaySetup-<version>.exe`

### `.spec` file requirements

Use `--onedir` mode. The spec should:

- Set `Analysis(...)` with `pathex=['src']`
- Include `hiddenimports`:
  - `pystray._win32`
  - `pystray._util.win32`
  - `PIL._tkinter_finder` (only if Pillow's ImageTk is used; safe to include either way)
  - `pygame._sdl2` if any v1.6 code touches it (audit; usually not needed)
- Add explicit `binaries` entries for SDL2 DLLs if PyInstaller's pygame hook misses them on the build machine. Audit `dist/CritterOverlay/` after first build for missing `SDL2.dll`, `SDL2_mixer.dll`, `SDL2_image.dll`, `SDL2_ttf.dll`. Add via `binaries=[(path, '.')]` only if missing.
- `excludes`: `unittest`, `test`, `tkinter.test`, `pydoc_data`, `pygame.tests`, and any other large stdlib or package internals not used at runtime. Keep `tkinter` itself: `settings_window.py` requires it.
- `EXE(...)`:
  - `console=False`
  - `icon='installer/icon.ico'`
  - `name='CritterOverlay'`
  - `version='installer/version_info.txt'` (generate a Windows version resource so Properties dialog shows correct info)
- `COLLECT(...)` produces `dist/CritterOverlay/` directory

Do not use `--onefile`. Reasons already settled: extraction overhead on every launch, higher AV false-positive rate, no real benefit when Inno wraps the output anyway.

### Inno Setup script requirements

`installer/installer.iss` setup section:

```
[Setup]

AppName=Critter Overlay
AppVersion=1.7.0
AppPublisher=Harrison Stagg

DefaultGroupName=Critter Overlay
DisableDirPage=yes
DisableProgramGroupPage=yes
PrivilegesRequired=lowest
PrivilegesRequiredOverridesAllowed=dialog
OutputDir=output
OutputBaseFilename=CritterOverlaySetup-1.7.0
Compression=lzma2/ultra
SolidCompression=yes
WizardStyle=modern
UninstallDisplayIcon={app}\CritterOverlay.exe
SetupIconFile=icon.ico
CloseApplications=yes
RestartApplications=yes
```

Critical points:

- `AppId` must be a fixed GUID. Generate once, never change. This is what enables in-place upgrades.
- `DefaultDirName={autopf}\Critter Overlay` resolves to Program Files when admin privileges are granted, or `%LOCALAPPDATA%\Programs\` when not. This is the modern Inno macro and handles per-user installs cleanly.
- `PrivilegesRequired=lowest` allows non-admin install. If the `keyboard` library testing reveals it requires elevation, change to `admin` and document.
- `CloseApplications=yes` lets Inno detect the running app and prompt to close it during upgrade. Combined with `RestartApplications=yes`, the app reopens after install.

`[Files]` section:
```
Source: "..\dist\CritterOverlay\*"; DestDir: "{app}"; Flags: recursesubdirs ignoreversion
```

`[Icons]` section:
```

Name: "{group}\Uninstall Critter Overlay"; Filename: "{uninstallexe}"
Name: "{autodesktop}\Critter Overlay"; Filename: "{app}\CritterOverlay.exe"; Tasks: desktopicon
```

`[Tasks]` section:
```

```

`[Run]` section:
```
Filename: "{app}\CritterOverlay.exe"; Description: "Launch Critter Overlay"; Flags: nowait postinstall skipifsilent
```

`[UninstallDelete]` section: empty by default. Do not list `%APPDATA%\CritterOverlay\`. The default behaviour preserves user data.

`[Code]` section: implement an optional uninstall checkbox to also remove user data. Pseudocode:

```

  // store answer in a bool, default NO

procedure CurUninstallStepChanged(CurUninstallStep: TUninstallStep);

    if AppDataDeleteOptIn then
```

| Item | Location |
|---|---|
| App binaries and bundled Python | `{app}` resolved as `{autopf}\Critter Overlay` |
| Settings | `%APPDATA%\CritterOverlay\settings.json` (unchanged from v1.6) |

### Update behaviour

In-place upgrade is the only supported path:
1. User runs new installer
2. Inno detects existing install via `AppId`
3. If app is running, Inno prompts to close (or closes silently if `RestartApplications=yes`)
4. Files in `{app}` are overwritten
5. App relaunches if it was running before
6. `%APPDATA%\CritterOverlay\` is untouched

Do not implement an in-app updater in v1.7. Add a "Check for updates" link in the System tab of settings that opens the GitHub releases page in the browser. This is the cheapest reliable solution.

### Uninstall behaviour

1. Stop the running app (Inno handles this if `CloseApplications=yes`)
2. Remove `{app}` and all contents
3. Remove start menu and desktop shortcuts
4. Remove autostart registry entry if present (the app sets one when "start with Windows" is on; uninstall must clean it up)
5. Prompt: "Also delete custom critters and settings? (default: no)". If yes, delete `%APPDATA%\CritterOverlay\`.
6. Remove Add/Remove Programs entry

## 3. Custom critter storage format

### Folder layout

```
%APPDATA%\CritterOverlay\
├── settings.json
└── custom\
    ├── fluffy-a3f2c1\
    │   ├── frames\
    │   │   ├── frame_0.png
    │   │   ├── frame_1.png
    │   │   ├── frame_2.png
    │   │   └── frame_3.png
    │   ├── masks\
    │   │   ├── mask_0.npy
    │   │   ├── mask_1.npy
    │   │   ├── mask_2.npy
    │   │   └── mask_3.npy
    │   ├── meta.json
    │   ├── thumb.png
    │   └── source.png
    └── derpy-b71e44\
        └── ...
```

Folder name format: `<slug>-<hash6>` where `slug` is a lowercased ASCII version of the critter name (spaces to hyphens, non-ASCII stripped) and `hash6` is the first 6 hex characters of a UUID4. This keeps folders human-recognisable while avoiding collisions.

Each critter is fully self-contained in its folder. Deleting the folder deletes the critter cleanly. This makes manual fixes, backup, and future export/import trivial.

### `meta.json` fields

```json
{
  "id": "fluffy-a3f2c1",
  "name": "Fluffy",
  "schema_version": 1,
  "created_at": "2026-05-15T14:32:00Z",
  "frame_count": 4,
  "frame_size": [120, 120],
  "import_method": "static_png",
  "procedural_animation": true,
  "source_dimensions": [256, 256],
  "trail_palette": ["#ffaa55", "#ff6633"],
  "sound_profile": "kitten",
  "sound_seed": 28471,
  "hit_radius_fallback": 55,
  "notes": ""
}
```

Field notes:

- `schema_version`: integer. Increment if the schema changes. Loader checks this and either upgrades or skips with a warning.
- `import_method`: enum of `static_png`, `static_jpg`, `animated_gif`, `drawn`. Used for diagnostics.
- `procedural_animation`: bool. True if frames were generated from a single source image; false if frames came from a multi-frame source (GIF).
- `frame_size`: stored at fixed canonical size (e.g. 120×120) regardless of display size. Display scaling is applied at render time.
- `trail_palette`: hex strings, top 2 dominant colours. Stored even though trail is off by default in v1.8, to avoid regenerating later.
- `sound_seed`: integer used to deterministically perturb sound parameters. Same seed always produces the same sound.
- `hit_radius_fallback`: used only if mask loading fails.
- `notes`: free text reserved for future use; empty string by default.

### Frame naming convention

`frame_<index>.png`, zero-indexed, contiguous integers.
- For procedural animation: always 4 frames (`frame_0` to `frame_3`)
- For GIF imports: variable, typically 4 to 8 frames after subsampling

### Thumbnail convention

`thumb.png`, 64×64 RGBA, generated from `frame_0` at import time. Used for the settings UI list. Always present.

### `source.png`

Original imported image, stored alongside frames. Allows re-running the import pipeline if the procedural animation is improved in a later version, without asking the user to re-upload. Not used at runtime.

For GIF imports, store as `source.gif` instead. For drawn critters (v1.9), store the canvas state as `source.png`.

### Integration with `settings.json`

Add a new top-level section:

```json
"custom_animals": {
  "fluffy-a3f2c1": {
    "enabled": true,
    "weight": 1.0,
    "sound_override": null,
    "size_override": null
  },
  "derpy-b71e44": {
    "enabled": false,
    "weight": 2.0,
    "sound_override": "duck",
    "size_override": null
  }
}
```

Field notes:

- Keys are critter IDs matching folder names
- `enabled`: bool, controls whether this critter is in the spawn pool
- `weight`: float, relative spawn weight, same units as built-in animals
- `sound_override`: string or null. If null, use `meta.sound_profile`. If set, use this preset instead.
- `size_override`: int or null. If null, use global `visual.size`. If set, override per-critter.

Default behaviour when a critter folder exists in `custom\` but no settings entry exists: create a settings entry with `enabled: true, weight: 1.0` and persist. This auto-registers manually-dropped critters.

Default behaviour when a settings entry exists but the folder does not: silently remove the orphan settings entry on next save. Log a warning.

## 4. Custom critter import pipeline

### Common pipeline

All import paths converge on a shared sequence after format-specific preprocessing:

1. Load source into Pillow `Image`
2. Validate (size, dimensions, content)
3. Convert to RGBA
4. Crop to bounding box of non-transparent pixels (with small padding)
5. Fit into canonical canvas (default 120×120, preserving aspect ratio with transparent padding)
6. Generate frames (procedural for static, extracted for GIF)
7. Generate alpha masks
8. Extract dominant-colour palette
9. Generate thumbnail
10. Pick default sound preset
11. Write all files to disk
12. Update `settings.json`

### PNG path

1. Load with Pillow
2. If source has alpha channel: use as-is
3. If source has no alpha: treat as JPG path (background removal)
4. Continue common pipeline with `import_method = "static_png"`

### JPG path

1. Load with Pillow, convert to RGB
2. Apply background removal (see below)
3. Convert to RGBA with alpha from removal step
4. Continue common pipeline with `import_method = "static_jpg"`

### Animated GIF path

1. Load with Pillow
2. Iterate frames (`ImageSequence.Iterator`)
3. If frame count >= 4: subsample to 4 evenly-spaced frames. If frame count > 8: subsample to 8.
4. If frame count < 4: duplicate frames to reach 4 (e.g. ABAB or ABBA pattern based on frame count)
5. Each frame: convert RGBA, crop to global bounding box (computed across all frames to keep alignment), fit into canonical canvas
6. Skip procedural animation step in common pipeline
7. `procedural_animation = false`, `import_method = "animated_gif"`

The bounding box must be computed across all frames, not per-frame, otherwise the critter will jiggle its position between frames.

### Drawing canvas path

Defer to v1.9. If a developer ships it in v1.8 anyway, the spec is:
- pygame surface, 512×512, transparent background
- Tools: brush (variable size), eraser, colour picker, fill, clear, undo (last 20 strokes)
- Output is RGBA Image
- Skip background removal in common pipeline
- `import_method = "drawn"`

### Background removal

`rembg` is the obvious tool but adds 100+ MB to the installer (uses U2Net). Not acceptable for a casual desktop toy.

Use a simple corner-based flood fill instead:


This works well for clean photos with uniform backgrounds (typical user upload). Fails for complex backgrounds.

Mitigation for failure cases:
- After background removal, show preview to user with original and processed versions side by side
- Buttons: "Looks good" and "Too aggressive / try transparent PNG instead"
- If user rejects: refuse the import, show message recommending they save a transparent PNG from another tool (e.g. remove.bg website, Photoshop, GIMP)

Do not attempt smart segmentation in v1.8. The complexity and bundle size cost is not justified.

### Alpha-mask generation

For each frame:
1. Extract alpha channel as numpy `uint8` array
2. Threshold: `mask = alpha > 32`
3. Dilate by 2 pixels using a 3x3 structuring element. Implementation: convolution with a 3x3 ones kernel via `scipy.ndimage.binary_dilation` if scipy is acceptable, otherwise a simple custom dilation via `numpy.maximum` shifts:

```python
def dilate_mask(mask: np.ndarray, iterations: int = 2) -> np.ndarray:
    out = mask.copy()
    for _ in range(iterations):
        shifted = (
            np.roll(out, 1, axis=0) | np.roll(out, -1, axis=0) |
            np.roll(out, 1, axis=1) | np.roll(out, -1, axis=1) |
            out
        )
        out = shifted
    return out
```

The numpy approach is fine and avoids adding scipy. Save mask as `.npy` (compact, fast load).

Audit decision: scipy is already not a dependency. Do not add it. Use the numpy version.

### Validation rules

Reject the import (with user-facing error) if:
- File size > 10 MB
- Source dimensions > 2048×2048
- Source dimensions < 32×32
- All pixels transparent or all pixels identical
- Non-transparent area < 5% of canvas
- Animated GIF with > 30 frames (likely a screen recording, not a sprite)

Warn (but allow) if:
- Non-transparent area is > 80% near-grey (likely a logo or text, will read poorly at small sizes)
- Source dimensions < 64×64 (will look pixelated when scaled up)
- Aspect ratio is more extreme than 1:3 (will look awkward in the perimeter walking mode)

All rejection messages must be plain English ("This image is too small. Please use at least 64x64 pixels.") not technical errors.

## 5. Custom critter runtime architecture

### `CustomAnimal` class

New file: `src/animals_custom.py`. Do not modify `animals.py` more than necessary.

Sketch:

```python
import math
import pygame
import numpy as np
from animals import Animal


class CustomAnimal(Animal):
    SPECIES = "custom"

    # Class-level defaults; instance overrides them at __init__
    LEAVES_TRAIL = False
    TRAIL_PALETTE = ()
    TRAIL_RATE = 0
    TRAIL_SIZE = 4
    TRAIL_LIFE = 0.6
    TRAIL_STAR = False

    def __init__(self, x, y, custom_id, registry, **kwargs):
        self.custom_id = custom_id
        self.registry = registry
        record = registry.get(custom_id)
        if record is None:
            raise ValueError(f"Unknown custom critter: {custom_id}")

        self.frames = record.frames           # list[pygame.Surface]
        self.masks = record.masks             # list[np.ndarray]
        self.meta = record.meta               # dict from meta.json
        self.frame_count = len(self.frames)
        self.frame_size = self.meta["frame_size"][0]  # assume square

        # Override class constants from this critter's metadata
        palette = self.meta.get("trail_palette") or []
        self.TRAIL_PALETTE = tuple(self._hex_to_rgb(c) for c in palette)
        # Trail off by default in v1.8 even if palette exists
        self.LEAVES_TRAIL = False

        # Speed: pick a moderate default. Could expose later.
        kwargs.setdefault("speed", 50)
        super().__init__(x, y, **kwargs)

        # Hit-test fallback if mask load fails
        self.hit_radius_fallback = self.meta.get("hit_radius_fallback", self.size * 0.46)

        # Cache for scaled frames keyed by (size, opacity)
        self._scaled_cache = {}

    def _get_scaled_frame(self, frame_idx: int) -> pygame.Surface:
        key = (frame_idx, self.size, self.opacity)
        if key not in self._scaled_cache:
            base = self.frames[frame_idx]
            scaled = pygame.transform.smoothscale(base, (self.size, self.size))
            if self.opacity < 255:
                scaled = scaled.copy()
                scaled.set_alpha(self.opacity)
            self._scaled_cache[key] = scaled
        return self._scaled_cache[key]

    def _current_frame_idx(self) -> int:
        # Map walk_phase (radians) to frame index
        return int(self.walk_phase * self.frame_count / (2 * math.pi)) % self.frame_count

    def draw(self, surface):
        if self.state == "POPPING":
            return  # particles handle the visual
        idx = self._current_frame_idx()
        sprite = self._get_scaled_frame(idx)
        if self.facing_left:
            sprite = pygame.transform.flip(sprite, True, False)
        rect = sprite.get_rect(center=(int(self.x), int(self.y)))
        surface.blit(sprite, rect)

    def hit_test(self, mx: int, my: int) -> bool:
        # Bounding box rejection first
        half = self.size / 2
        if not (self.x - half <= mx <= self.x + half and
                self.y - half <= my <= self.y + half):
            return False

        if not self.masks:
            # Fallback to circle
            return math.hypot(mx - self.x, my - self.y) <= self.hit_radius_fallback

        idx = self._current_frame_idx()
        mask = self.masks[idx]
        mh, mw = mask.shape

        # Convert global to local coordinates in mask space
        local_x = (mx - self.x + half) * (mw / self.size)
        local_y = (my - self.y + half) * (mh / self.size)

        if self.facing_left:
            local_x = mw - 1 - local_x

        ix, iy = int(local_x), int(local_y)
        if 0 <= ix < mw and 0 <= iy < mh:
            return bool(mask[iy, ix])
        return False

    def emit_trail(self):
        # v1.8: no trail. Override to no-op.
        return []

    @staticmethod
    def _hex_to_rgb(hex_str: str) -> tuple[int, int, int]:
        s = hex_str.lstrip("#")
        return (int(s[0:2], 16), int(s[2:4], 16), int(s[4:6], 16))
```

### Inheritance from `Animal`

`CustomAnimal` inherits all of: position, velocity, state machine (WALKING/IDLE/TURNING/POPPING), free-roam movement, perimeter walking, idle pauses, drag physics, throw physics with gravity and spin, pop particle generation, sound playback hook, blink timing.

Only `draw()`, `hit_test()`, and `emit_trail()` need overrides in v1.8.

Do not refactor `Animal` to extract a shared base in v1.8. Inheritance with selective overrides is sufficient. Refactor in v1.9 if and when it becomes painful.

### Frame selection mapping

`walk_phase` accumulates as `walk_phase += speed * dt * k` (existing logic in `Animal._update_walking`). For built-ins, leg bob is `sin(walk_phase * 2)`. For custom critters with 4 frames, map one full cycle of `walk_phase` (0 to 2π) to all 4 frames:

```python
frame_idx = int(walk_phase * frame_count / (2 * math.pi)) % frame_count
```

This means at walking speed, a custom critter cycles through frames at roughly the same rate as built-ins bob their legs. If it feels too fast or slow during testing, scale `walk_phase` for custom critters or expose a `frame_period_multiplier` in meta.json (defer to v1.9).

### Horizontal flipping

Frames are stored facing right by convention. When `facing_left` is True:
1. `pygame.transform.flip(frame, True, False)` for rendering
2. Mirror x coordinate when looking up in mask: `local_x = mask_width - 1 - local_x`

Both are O(1) per frame. The flip operation creates a new Surface per call; for performance, cache flipped versions if profiling shows it matters. Initial implementation: don't cache, measure, then optimise if needed.

### Opacity and size

Read from global config (`visual.size`, `visual.opacity`) at instance creation. Store as `self.size` and `self.opacity`. Per-critter overrides come from the settings.json `custom_animals.<id>.size_override`.

When config changes (settings window edit), the existing `apply_config()` flow on the spawn manager should iterate live animals and update their `size` and `opacity`. CustomAnimal's `_scaled_cache` is keyed on `(frame_idx, size, opacity)` so cache entries automatically invalidate when those change; old entries leak slowly but the cache is small. Add a `clear_cache()` method called from `apply_config()` for cleanliness.

### Spawn integration

`spawn_manager.py` currently picks species from a weighted pool of built-in animals based on the `animals` config section. Extend this:

1. At spawn time, build the pool from both built-in animals (where `enabled=True`) and custom critters (where `custom_animals.<id>.enabled=True`)
2. Each pool entry is `(species_or_id, weight, factory)` where factory is a callable that creates the right Animal subclass
3. Weighted random pick selects one
4. The rare-roll logic (1/100 unicorn, 1/1000 golden) applies regardless: each individual still rolls independently

Custom critters spawn alongside built-ins with no special handling. They use the same group spawn and solo perimeter mechanics.

A custom critter cannot be a "rare" itself in v1.8. (Defer to v1.9 if there is appetite for it.)

## 6. Hit detection design

### Algorithm

```
def hit_test(mouse_x, mouse_y) -> bool:
    1. Compute sprite bounding box from (x, y, size)
    2. If mouse not in bounding box, return False
    3. If no masks loaded, fall back to circle hitbox using hit_radius_fallback
    4. Look up current frame index from walk_phase
    5. Translate mouse coords to mask space:
       local_x = (mouse_x - x + size/2) * (mask_width / size)
       local_y = (mouse_y - y + size/2) * (mask_height / size)
    6. If facing_left, mirror x: local_x = mask_width - 1 - local_x
    7. Round to integer and bounds-check
    8. Return mask[iy, ix]
```

### Coordinate transforms

Sprite is rendered centred on `(x, y)` at display dimensions `(size, size)`. Mask is stored at `(mask_width, mask_height)` matching the canonical frame size (e.g. 120×120). The display size may differ from mask size due to user's visual.size setting (80–200).

Therefore the transform requires a scale factor `mask_width / display_size`. Always compute at lookup time, do not cache (cheap).

### Flipped sprites

When `facing_left`, the rendered sprite is flipped horizontally. The mask is not pre-flipped; instead, mirror the lookup x-coordinate. This avoids storing 2x masks per critter.

### Mask dilation

Dilate by 2 pixels at import time. Stored mask is the dilated version. This gives a forgiving click target without runtime cost. 2 pixels is a good starting point; increase to 3 if user testing reports clicks feel unforgiving.

Do not store both dilated and undilated masks. The original alpha is recoverable from the frame PNG if needed.

### Performance

Hit detection is called only on click events (one event = one or a few hit tests across animals on screen, breaks early on first hit). It is not called per frame. Cost is dominated by the bounding box rejection. Numpy mask access for non-rejected animals is microseconds.

No optimisation needed. If profiling later shows otherwise, options include:
- Spatial partitioning of animals
- Pre-computing bounding rect per frame

Neither is needed in v1.8.

### Fallback behaviour

If mask file is missing, corrupt, or fails to load:
- Log warning at startup
- Use circle hit detection with `hit_radius_fallback` from meta
- Critter remains usable, just less accurately clickable

If meta.json is missing or invalid:
- Skip the critter entirely
- Log error
- Remove from registry
- Settings entry remains in case the user fixes the folder later

## 7. Procedural animation design

### Goal

Take one static image, produce 4 frames giving a "bouncing/waddling" feel. Set user expectation as "desktop critter that hops and waddles" not "smoothly walking sprite".

### Frame count

Always 4 for procedural. More frames cost storage and import time and add zero perceived smoothness at the speed critters move on screen.

### Per-frame transforms

Frame 0 (neutral):
- No transform

Frame 1 (squash and lean forward):
- Scale: x=1.03, y=0.95
- Rotate: -2 degrees
- Translate: y +2 px

Frame 2 (stretch and rise):
- Scale: x=0.97, y=1.05
- Rotate: 0 degrees
- Translate: y -3 px

Frame 3 (squash and lean back):
- Scale: x=1.03, y=0.95
- Rotate: +2 degrees
- Translate: y +2 px

The cycle is 0 → 1 → 2 → 3 → 0. This produces a gentle bob with subtle weight shift.

### Implementation

Use Pillow:
1. Load source image as RGBA
2. Compute output canvas size with margin for rotation: `output_size = source_size + 8 px`
3. For each frame:
   a. Apply scale via `Image.resize`
   b. Apply rotation via `Image.rotate(angle, resample=BICUBIC, expand=False)`
   c. Paste onto blank RGBA canvas at centre + translation offset
4. Save each as `frame_N.png`

### Consistency with built-ins

Built-in walk cycle: leg bob `sin(walk_phase * 2)`, head bob `sin(walk_phase + 0.5)`. Both run at speeds of around 1–2 cycles per second at typical walking speed.

Procedural animation should match: 4 frames over `walk_phase` 0 to 2π, which is 1 full cycle per `2π / (speed * k)` seconds. Tune `k` so a custom critter at default speed (50 px/s) cycles roughly once per second.

Test: spawn a Kitten and a custom critter side by side. The custom should not feel obviously slower or faster than the kitten's leg bob.

### What not to attempt yet

- Skeletal detection or limb articulation
- Per-region deformation (e.g. animating just the legs)
- Tail or ear secondary motion
- Idle-vs-walking distinction (just animate continuously, accept that idle critters will still bob slightly)
- Direction-aware lean (always lean the same way regardless of facing direction)

These are all v1.9+ if they are ever needed. Most are not.

### Edge cases to handle

- Source with extreme aspect ratio: still apply transforms but the result will look odd. Validation rule already warns the user during import.
- Very small source: scaling up is unavoidable. Use BICUBIC resampling consistently. Accept the result.
- Source with mostly transparent edges: rotation may clip. The 8px margin handles most cases. If clipping is visible, increase margin; do not reduce rotation amount.

## 8. Sound and trail design

### Sound presets

Use the existing 8 procedural sound generators as presets: kitten, turtle, duck, rabbit, hedgehog, squirrel, otter, panda. No new sounds needed for v1.8.

Default assignment at import:
- Hash the critter name with `hash(name) % 8` (or use a stable hash like `int(hashlib.md5(name.encode()).hexdigest()[:8], 16) % 8`)
- Map to one of the 8 presets
- Store in `meta.sound_profile`
- User can override in settings dropdown

### Deterministic variation

Each critter gets a `sound_seed` (random integer at import time, stored in meta). When playing the sound:
1. Look up the preset generator
2. Pass the seed as an additional parameter
3. Generator perturbs frequencies by ±5%, envelope times by ±10%, harmonic ratios by ±3%

Modify each existing sound generator to accept a `seed` parameter (default 0 = no perturbation, preserves existing built-in sounds exactly). When seed is non-zero, use a `random.Random(seed)` instance to derive the perturbations deterministically.

Result: same critter sounds the same every time; different critters with the same preset sound subtly different.

Do not expose synthesis parameters in the UI. Too much complexity, too little gain.

### Trail palette

Auto-extracted at import (top 2 dominant non-grey colours). Stored in `meta.trail_palette` even though trail is off by default in v1.8.

`LEAVES_TRAIL = False` for all custom critters in v1.8. This preserves trails as a rare-creature signal (unicorns and golden kittens stay special).

### Trail style selection

Defer to v1.9. UI complexity not justified for v1.8 timeline. The palette is already extracted and stored, so v1.9 can add a toggle without re-importing critters.
