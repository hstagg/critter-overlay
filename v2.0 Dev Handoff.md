## 1. Executive summary

Critter Overlay v2.0 should become **a living version of v1** — the same app, but where critters feel like animals rather than wandering sprites, and where the desktop is a small world that breathes with the time of day. Not a pivot, not a rewrite. The app's identity (ambient cartoon critters wandering your screen, zero-friction install, no accounts, no cloud) is working. v2.0 adds four threads on top of that foundation:

1. **A living-world layer** — species-specific locomotion (kittens pounce, rabbits hop in arcs, ducks waddle, turtles plod, otters roll), a large catalogue of solo idles and two-critter interactions (sniffs, follows, chases, grooming, play-bows, stare-contests, naps), and a day/night cycle that shifts behaviour and activity through the day (slower in the evening, lots more napping at night). No visual tinting — the app stays a true transparent overlay. This is what makes the screen feel alive.
2. **A rarity layer** — every spawned critter rolls a hidden tier (Common → Legendary) that manifests as subtle visual flair (aura, trail, higher interaction rate). No achievements, no grind. Just "huh, that one looked special."
3. **A `.critter` sharing format** — a zipped, validated, locally-imported container so users can swap critters with friends without uploading to a server.
4. **A UX/visual polish pass** — consolidate the settings window from 6 tabs to 4, fix the inconsistency between built-in and custom critter controls, add a first-run welcome, swap key widgets to `sv-ttk` themed ttk for a more modern feel. **Stay in tkinter.**

The v1 codebase is competent. v2.0 is about *making the world feel alive and finished*, not redesigning it.

## 2. Non-negotiables

These must survive v2.0 unchanged:

- **Desktop-pet ambience.** Critters wander; they do not demand attention. No notifications, no toasts, no daily quests, no streaks.
- **Frictionless install.** Distribution stays a single Inno Setup `.exe` installer wrapping a PyInstaller bundle. No Python prerequisite, no venv build, no extra files for the user to handle. Bundle size should not balloon — every added MB is a real download cost for users on slow connections.
- **Windows-first.** No cross-platform work in v2.0. Win32 layered window, pystray, `keyboard` library, named mutex all stay.
- **No accounts. No cloud. No telemetry.** All state lives in `%APPDATA%`. Sharing is file-based (drag a `.critter` onto the app).
- **Public-repo hygiene.** No personal data, no vault conventions, no private context anywhere in committed files.
- **Chroma-key magenta `(255, 0, 255)` stays.** Changing it breaks every existing built-in sprite and is not on the table.
- **Existing user settings load cleanly.** Config schema is additive only; unknown keys preserved; new keys default-merged. v1 custom critters in `%APPDATA%\CritterOverlay\custom\` continue to work without manual migration.
- **Lightweight.** No new heavyweight dependencies (PySide6, scipy, opencv, etc.). Every added MB hits first-launch install time directly.

## 3. Current state audit

### What works well
- **Clean module separation.** `main.py` (tray + lifecycle), `overlay.py` (pygame render loop), `animals.py` (8 built-in species), `spawn_manager.py`, `config.py`, `settings_window.py`. Roles are clear.
- **The release pipeline is solid.** `release.ps1` + `build.ps1` + `CritterOverlay.spec` + Inno Setup produces a signed-style installer in one command. PyInstaller bundles Python and all dependencies; users never see Python. (The legacy `__main__.py` zipapp bootstrap is still in the tree but no longer the shipping path.)
- **Config layer is forward-compatible.** `config.py` deep-merges user config with `DEFAULT_CONFIG`, so adding new keys never breaks old saves.
- **Custom critter pipeline is more sophisticated than it needs to be.** Corner flood-fill bg removal, procedural walk generation (bob + lean + stride shear), alpha-mask dilation for forgiving hit-tests, dominant-colour palette extraction for trails. The work is real.
- **Physics feel right.** Elastic equal-mass collisions, scatter threshold, momentum transfer on throw. Tuned.
- **Sound system is deterministic per critter.** Hash-based seed gives each custom critter a consistent voice without storing audio.

### What's fragile
- **`animals.py` is a 1384-line god module.** One base class doing physics + state machine + animation + drawing + particle emission, plus 8 species classes. Adding rarity auras or new states means touching the same file for everything.
- **`settings_window.py` is 1934 lines.** Most of the UI work in v2.0 lands here. The structure is reasonable (tab classes, factory methods for sliders/cards), but it's near the limit of what's pleasant to navigate.
- **Threading model has no synchronisation.** Tk settings window runs on a daemon thread and writes `overlay.config` directly. Global hotkey callback (from `keyboard` lib) mutates `overlay.paused` from yet another thread. CPython's GIL hides this today; it's a latent footgun.
- **Collision detection is O(n²)** in `overlay._resolve_collisions()`. Fine at current spawn caps (~20 critters). Don't raise the cap without a spatial hash.
- **Bg-removal failure modes are silent.** Corner flood-fill breaks on gradients, textured backgrounds, and critters whose edge colour matches a corner pixel. The user gets a wrongly-cropped critter with no diagnostic and no recovery path.
- **Hardcoded rare-species checks** scattered across `spawn_manager.py` and `main.py` (golden kitten 1/1000, unicorn 1/100). Adding rarity properly means replacing this pattern, not extending it.
- **Custom critter sound assignment is hash-derived from name.** Rename a critter, its voice changes. The v1.10 work added a `sound_file` override path, which mostly fixes this but adds a new fragility (what if the file moves?).
- **No `schema_version` migration logic in `meta.json`.** Fields are defaulted on load, which works for additive changes but means there's no path for a real format change.
- **First-launch UX is silent.** Bootstrap window closes; tray icon appears; nothing tells the user the settings exist or how to find them.

### "Do not touch casually"
- `_resolve_collisions()` thresholds in `overlay.py` (`SCATTER_THRESHOLD`, `MIN_SCATTER_SPD`). Frame-rate-dependent. Tuning regressions are subtle.
- The `__main__.py` two-pass bootstrap. If you break this, first-launch breaks for every new user.
- Windows mutex `CritterOverlayMutex_v1`. Renaming it allows a second instance during the upgrade window.
- The chroma-key colour `(255, 0, 255)`. See §2.
- `CustomAnimal._scale_cache` keyed by `(frame_idx, size, flip)` — load-bearing for perf.

**"Critter Overlay v2.0: A living desktop."**

Four coherent threads, each visible to users:

- **Living world** is the headline. Species-specific locomotion makes a kitten look like a kitten and a duck look like a duck. A wide catalogue of solo idles and pair interactions means something interesting happens every few minutes. A day/night cycle shifts the mood across the day.

## 5. Major feature pillars

### Pillar 0 — Living world layer (species locomotion, interactions, day/night)

**User-facing goal.** Open the app. A rabbit hops past in arcs (not walks). A kitten pounces forward, freezes, pounces again. Two critters meet, sniff each other, then split. Later, a kitten chases a squirrel briefly. As evening sets in, critters move more slowly with more naps; at night spawns are sparser and quieter. The screen feels like a small world, not a sprite parade — and the overlay stays fully transparent. No screen tint, no compositing artefacts.

**Three sub-systems** that together create the living-world feel — see §7 for the full spec.

1. **Species locomotion.** Each built-in species gets a movement profile that isn't just `speed * direction`. Kittens have pounce-pause-pounce. Rabbits hop in low arcs. Ducks waddle (sinusoidal side-to-side). Turtles plod with head-bob. Otters occasionally belly-slide. Squirrels dart in zigzags with freeze-and-look pauses. Hedgehogs snuffle. Pandas lumber. Custom critters get a configurable locomotion profile in `meta.json` (default: classic walk, backwards-compatible).
2. **Interaction & idle catalogue.** ~40+ named behaviours covering solo idles (stretch, yawn, scratch, look-up-at-cursor, nap, sneeze, shake-off, species-flavoured idles like duck-preen and rabbit-nose-twitch) and two-critter interactions (sniff, follow, chase, mutual-groom, bow, stare-contest, bump-recoil, walk-together). Trigger logic is timer + proximity + cooldown based.
3. **Day/night cycle (behaviour-only).** System clock drives an activity scalar and spawn-rate scalar. Six time buckets: Dawn, Morning, Midday, Afternoon, Evening, Night. Evening is slower; night is much slower with more sleeping idles and sparser spawns. **No visual tinting** — the overlay stays a clean transparent surface. The "mood" is conveyed entirely through how critters move and how often they appear.

**Implementation outline.**
- New `src/locomotion.py` — locomotion profile dataclass + per-profile update function (called from `Animal.update()`).
- New `src/behaviours.py` — registry of solo idles and pair interactions, trigger evaluator, behaviour state machine extension.
- New `src/time_of_day.py` — returns current bucket, activity scalar, spawn-rate scalar; called once per second from spawn manager and behaviour evaluator. Not called from the per-frame draw path (no visual application).
- `animals.py` base class: extend state machine to include behaviour states (GROOMING, SNIFFING, NAPPING, POUNCING, etc.); delegate movement to the locomotion profile.
- `spawn_manager.py`: behaviour-trigger evaluator runs once per second across all alive critters, picks compatible pair-interactions with a small budget.
- Each built-in species class declares its locomotion profile and which idles it can perform.
- Custom critters get `locomotion: "classic" | "hop" | "waddle" | "plod" | "dart" | "slide" | "snuffle" | "lumber"` in `meta.json` (default `"classic"` for v1 critters).

**Files affected.** New: `locomotion.py`, `behaviours.py`, `time_of_day.py`. Modified: `animals.py` (every species needs a small declaration block; base class extended), `animals_custom.py` (read locomotion from meta), `spawn_manager.py` (interaction trigger loop, spawn-rate scalar from time-of-day), `config.py` (toggles for day/night, interaction frequency). `overlay.py` does **not** change for tinting — the draw path remains exactly as v1.

**Risks.**
- *Performance* — pair-interaction evaluation is O(n²) on top of existing collision O(n²). Mitigation: only re-evaluate every ~1s, not every frame; budget at most 1 new pair-interaction per evaluation.
- *State machine complexity* — adding ~10 new behaviour states to `animals.py` risks a tangle. Mitigation: behaviour states are short-lived and time-bounded; they always return control to WALKING.
- *Visual jank* — locomotion profiles fighting with existing physics (collision response, drag, throw). Mitigation: locomotion only drives velocity in the WALKING state; physics overrides apply normally in SCATTERED / dragged / thrown states.

**Testing.** Visually inspect each species after locomotion implementation — they should be recognisable from movement alone. Run a 30-minute idle session, log all triggered behaviours, confirm at least 15 distinct behaviours fire. Confirm pair-interactions trigger at the expected rate. Confirm day/night behaviour shifts across an accelerated time test (override system clock for testing) — evening critters slow down, night spawns sparser, more naps.

**Priority.** P0 — this is now the headline feature, ahead of rarity.

## 6. Rarity and spawn system proposal

### Tier definitions

| Tier | Default spawn share | Aura | Trail default | Speed variance | Personality fire rate |
|---|---|---|---|---|---|
| Common | 60% | none | none | 0.8–1.0× | 30% |
| Uncommon | 25% | soft outline glow | dots | 0.9–1.1× | 50% |
| Rare | 10% | bright pulsing halo | sparkles | 0.95–1.05× | 70% |
| Epic | 4% | shimmer/distortion ring | glitter | locked 1.0× | 85% |
| Legendary | 1% | rainbow cycling halo | hearts (or per-species override) | locked 1.0× | 100% |

Distribution is configurable in `config.json` under `rarity.distribution`. Defaults above. Sum must equal 1.0; on save, normalise.

### Per-species rarity floor / ceiling

Some species feel wrong at certain tiers (a Legendary turtle reads as a bug, not a feature). Each species in `DEFAULT_CONFIG` gains:
```python
"rarity_min": "common",     # never rolls below this
"rarity_max": "legendary",  # never rolls above this
```
Defaults: all species `common`–`legendary` except Turtle/Panda capped at `epic`.

### Rare-hour event

A configurable daily one-hour window (default 21:00–22:00 local) doubles Rare/Epic/Legendary odds at the expense of Common. No notification. The point is "if you happen to glance, you'll see something cool more often." Configurable on/off in Behaviour tab.

### First-spawn-of-day

The first critter spawned after midnight local is guaranteed Rare-or-better, with a single Legendary roll at higher-than-normal odds. No popup. Tracked via `last_first_spawn_date` in config.

### Custom critters and rarity

Custom critters get a `rarity_strategy` field in `meta.json`:
- `"auto"` (default) — rolls per the same distribution as built-ins.
- `"fixed:<tier>"` — always spawns at that tier. Users can manually mark a critter as "always Legendary" if they made something special.
- `"common_only"` — opts out of the rarity system entirely (renders as v1).

### Example schema

```json
{
  "rarity": {
    "enabled": true,
    "distribution": {
      "common": 0.60,
      "uncommon": 0.25,
      "rare": 0.10,
      "epic": 0.04,
      "legendary": 0.01
    },
    "rare_hour": {
      "enabled": true,
      "start_hour": 21,
      "duration_minutes": 60,
      "rare_tier_boost": 2.0
    },
    "first_spawn_of_day_bonus": true,
    "seen_log_enabled": true
  }
}
```

### What rarity does *not* do
- No XP, no levelling, no unlocks.
- No "complete your collection" prompts.
- No timed/expiring critters.
- No leaderboards or comparison with other users.
- No achievement toasts.

Rarity is purely a *render-time visual modifier* plus a passive log. It changes how a critter looks for the seconds it's on screen, and that's it.

## 7. Living world spec — locomotion, behaviours, day/night

This is the most under-specified pillar in the rest of the doc, so the spec is fleshed out here. An implementer should treat this as the design contract.

### 7.1 Locomotion profiles

A locomotion profile is a function `(animal, dt) -> velocity` that overrides the simple `speed * direction` of v1's `WALKING` state. Each profile has its own micro-rhythm. Speed-multiplier and direction reversals still come from the existing animal state; the profile shapes the *texture* of movement.

| Profile | Used by | Movement texture |
|---|---|---|
| `classic` | (custom critters, default) | v1 smooth walk. Speed * direction. |
| `pounce` | Kitten | Pounce-pause-pounce: 0.4s burst at 1.6× speed, 0.6s hold near zero, repeat. Small bob during burst. |
| `hop` | Rabbit | Hop arcs: 0.5s arc (sinusoidal vertical + forward), 0.3s ground hold. Effectively a low jump every beat. |
| `waddle` | Duck | Side-to-side body sway (small horizontal sinusoid) at 1.5 Hz, layered onto steady forward speed. |
| `plod` | Turtle | Slow steady speed, exaggerated head-bob, occasional 1-frame stutter to look like effort. |
| `dart` | Squirrel | Bursts of 0.25s at 2× speed, then 0.4s freeze-and-look (zero velocity, idle head turn). Occasional zigzag (direction tweak by ±15°). |
| `slide` | Otter | Mostly classic walk, but ~20% of the time enters a 1.0s belly-slide: prone sprite, smooth glide at 1.3× speed, no bob. |
| `snuffle` | Hedgehog | Slow steady speed, exaggerated low head-bob, slight side-to-side nose sweep. |
| `lumber` | Panda | Very slow, heavy weight-shift sway (long-period horizontal sinusoid), occasional 1.5s standing pause. |

**Implementation:** each profile is a small dataclass:
```python
@dataclass
class LocomotionProfile:
    name: str
    speed_envelope: Callable[[float], float]   # time-in-cycle → speed scalar
    vertical_offset: Callable[[float], float]  # time-in-cycle → y offset
    cycle_duration: float                       # seconds
    pause_probability: float                    # chance per cycle to insert a brief pause
```
Profile update runs per frame; pause insertion runs per cycle. Keep it functional and stateless — store cycle phase on the Animal.

**Custom critters:** `meta.json` gains `locomotion: "classic"` (default). Users can pick from the same 9 profiles. UI: dropdown in the custom critter card. v1 critters auto-default to `classic` — no visual regression.

### 7.2 Behaviour catalogue

The goal is ~40+ behaviours so something interesting fires every 1–3 minutes in typical use. Behaviours are split into solo idles (one critter) and pair interactions (two critters near each other).

**Solo idles (universal — any species can do these):**

| # | Name | Duration | Description |
|---|---|---|---|

### 7.3 Behaviour trigger logic

- Every 1.0s, the behaviour evaluator runs.
- For each alive critter not currently in a behaviour state, roll its `behaviour_chance` (base 0.05 per tick, modified by rarity tier, current time-of-day activity scalar, and species personality).
- If a solo behaviour rolls: pick a compatible idle from the species' whitelist, weighted by recency (don't repeat the same one in succession).
- For pair-interactions: scan alive critters for compatible pairs within proximity threshold (~80px), respecting per-pair cooldowns (default 30s). Pick at most one new pair-interaction per tick.
- Hard cap: no more than 25% of alive critters in a behaviour state simultaneously (don't freeze the whole screen).

### 7.4 Day/night cycle (behaviour-only, no visual tint)

System clock drives behavioural scalars, recomputed once per second. **Nothing is drawn differently.** The overlay stays a clean transparent surface at every hour. The cycle is felt through how critters act, not how they look.

| Bucket | Hours | Activity scalar | Spawn-rate scalar | Sleep-idle bias | Notes |
|---|---|---|---|---|---|
| Dawn | 05:00–08:00 | 0.9 | 0.8 | low | Quiet, waking up |
| Morning | 08:00–11:00 | 1.1 | 1.2 | very low | Perky, more spawns |
| Midday | 11:00–15:00 | 1.0 | 1.0 | low | Baseline |
| Afternoon | 15:00–18:00 | 1.0 | 1.0 | low | Baseline |
| Evening | 18:00–21:00 | 0.8 | 0.9 | medium | Slower, more sitting and grooming |
| Night | 21:00–05:00 | 0.5 | 0.5 | high | Sparse, lots of napping idles |

Scalars apply where:
- **Activity scalar** multiplies a critter's effective `speed_multiplier` for the WALKING state.
- **Spawn-rate scalar** multiplies the spawn manager's base spawn frequency.
- **Sleep-idle bias** weights the idle picker toward `nap` / `sit_and_look` / `groom_self` over more active idles like `scratch` or species-specific hunt-poses.

Transitions across bucket boundaries are linear over a 10-minute window so the change is gradual rather than snapping at the hour.

**User controls (Behaviour tab):**
- `day_night_enabled` (default true) — master toggle. Off = baseline scalars at every hour.
- `behaviour_frequency` (default 1.0, range 0.3–2.0) — multiplier on `behaviour_chance` ticks.
- `interactions_enabled` (default true) — toggle pair-interactions specifically.

**What this is not:** there is no screen tint, no sprite tint, no compositor change, no extra draw work. `overlay.py`'s render path is byte-for-byte the same as v1. This is purely a data-layer signal feeding the spawn manager and behaviour evaluator.

### 7.5 What this layer does *not* do

- No persistent relationships across sessions (no "Kitty and Ducky became friends yesterday"). Pair affinities are session-local at most.
- No sleep/awake state that survives a restart.
- No weather, no environmental objects (deferred to v2.1+ — see §14).
- No critter mood tracking beyond the current behaviour state.
- No multi-monitor awareness for behaviours (interactions only fire on the active overlay).

## 8. GUI/UX redesign proposal

### Recommendation: keep tkinter, augment with `sv-ttk`

The current dark UI is custom-built and works. The PyInstaller .exe distribution removes the old zipapp/venv argument against bigger GUI frameworks, but the case for staying in tkinter still holds:

- **Bundle size matters.** PySide6 adds roughly 40–60 MB to the installer (Qt DLLs, plugins). Users on slow connections feel that. CustomTkinter is lighter (~5 MB) but its synthetic widgets feel off on Windows.
- **PyInstaller compatibility risk.** Tkinter is rock-solid under PyInstaller. PySide6 needs careful spec-file work (Qt plugins, platform DLLs); CustomTkinter pulls extra assets that PyInstaller sometimes misses. Adding either is non-zero ongoing maintenance.
- **The visual ceiling isn't the bottleneck.** v1's UX problems are jargon, IA, and inconsistency — not "tkinter doesn't look modern enough". A redesign in tkinter solves the real complaints.
- **Migration cost.** A framework switch means rewriting ~1900 lines of `settings_window.py`. That's effectively all of v2.0's UX budget burned on plumbing.

`sv-ttk` is a pure-tcl ttk theme (~500KB, no compiled binaries) that adds modern slider/button/combobox styling without changing how widgets are wired. It's the lowest-risk, highest-leverage upgrade.

If a framework migration becomes attractive later, **CustomTkinter is the next step to consider** — it preserves the tkinter event model so migration is incremental rather than a full rewrite. PySide6 should stay rejected unless v3.0 wants something tkinter genuinely can't do (proper animations, rich text, native accessibility APIs).

### Settings IA — 4 tabs

**Critters**
- Import buttons at top: `Import critter` · `Import from frames` · `Import .critter file`.
- Built-in species cards (toggle, spawn frequency, speed, activity level, animation trail) — all inline, no gear panel.
- Custom critter cards below — same controls inline, plus rarity strategy, size, sound, rename, export, delete.

**Behaviour**
- Spawning: group frequency, group size, solo perimeter walker, rarity distribution, rare-hour config.
- Visuals: animation quality, max simultaneous critters, animation style preset.

**Audio**
- Master toggle, master volume.
- One scrollable list of every critter (built-in + custom) with per-critter sound toggle and preview button.

**System**
- Auto-launch on startup.
- Hotkey reference (and remap, if Pillar E ships).
- Update checker status.
- "Critters I've seen" (collapsed by default; opens the rarity log).
- About / version / quit.

### Visual style guidance

- Palette: keep existing violet/cyan accents. Slightly darken sidebar (`#0d0d1a`), slightly warm content background (`#14142a`).
- Card padding: 16h × 14v. Card gap: 8px. Border radius via sv-ttk where possible; flat corners otherwise.
- Typography: Segoe UI throughout. 16/12/10/9 for h1/card-title/body/caption.
- Sidebar nav stays. Don't switch to top tabs.
- Cards-over-rows stays. Don't switch to dense tables.

### First-run modal

## 9. Custom critter v2 proposal

### Import flow improvements (P1)

1. **Preview before commit.** After file selection, generate frames in memory and show animated preview. User accepts (commits to disk), adjusts (opens personality controls), or cancels (nothing written).
2. **Alternative bg removal as fallback.** Primary stays corner flood-fill. If the user clicks "Try transparent background", offer one alternative pass (looser tolerance + edge feathering). No more than one alternative — this isn't an image editor.
3. **Edge feathering on alpha threshold.** Apply 1px Gaussian to the alpha channel to smooth anti-aliased fringes. Cheap, large visual win.
4. **Strip EXIF/metadata** on source-image copy. Privacy hygiene; takes 3 lines with Pillow.

### `.critter` sharing format (P0)

Zip structure:
```
mycritter.critter            (zip)
├── meta.json                schema_version=2, name, author, license, attribution_url, app_min_version, frame_count, …
├── manifest.json            { content_hash, app_min_version }
├── frames/
│   ├── frame_0.png
│   └── …
├── masks/                   (optional — regenerated on import if absent)
│   └── …
├── sounds/                  (optional)
│   └── walk.wav
├── source/                  (optional, for re-import)
│   └── original.png
└── thumb.png                (optional)
```

### `meta.json` v2 schema

```json
{
  "schema_version": 2,
  "id": "fluffy-x7a3b1",
  "name": "Fluffy",
  "author": "anonymous",
  "license": "cc-by-4.0",
  "attribution_url": null,
  "app_min_version": "2.0.0",
  "created_at": "2026-06-01T12:00:00Z",
  "frame_count": 4,
  "frame_size": [120, 120],
  "import_method": "single_image",
  "procedural_animation": true,
  "trail_palette": ["#ff8866", "#ffaaaa", "#ffeebb"],
  "sound_profile": "chirp",
  "sound_file": null,
  "sound_seed": 12345,
  "rarity_strategy": "auto",
  "size_multiplier": 1.0,
  "speed_multiplier": 1.0,
  "idle_rate": 0.003,
  "trail_style": "none",
  "notes": ""
}
```

### Migration plan

- On load, any `meta.json` without `schema_version` → treated as v1, upgraded in memory.
- Missing v2 fields are filled with defaults (`license: "unknown"`, `author: "imported"`, `rarity_strategy: "auto"`).
- Upgraded `meta.json` is rewritten to disk on next mutation, not eagerly (preserves user's existing files until they actually change something).

### Validation rules (`.critter` import)

- Total zip size ≤ 50 MB.
- File count in zip ≤ 100.
- Per-file size ≤ 10 MB.
- Frame count ≤ 32.
- Allowed extensions only: `.png`, `.json`, `.wav`, `.txt`, `.md`.
- All paths inside zip relative; reject any containing `..`, absolute paths, or null bytes.
- `meta.json` must parse and contain `{id, name, schema_version}`.
- Frame dimensions match declared `frame_size` ±10%.
- Reject if any `.wav` exceeds 2 MB or 30 seconds.

### Export

- Right-click custom critter card → Export → file picker → write `.critter` to chosen location.
- Default filename: `<name>.critter`.
- Include `source/` and `sounds/` only if they exist on disk for that critter.

### Sharing model

- File-based only. Users share via Discord / email / GitHub / USB. No marketplace, no built-in browsing, no upload, no servers.
- Drag-and-drop a `.critter` onto the overlay window → import. Implemented via SDL2's file-drop event (pygame raises this natively).
- On import from `.critter`, show a small confirm dialog: critter name, author, license, "Install?" Y/N.

### Backwards compatibility

- v1 critters in `%APPDATA%\CritterOverlay\custom\<slug>-<hash>\` continue to work unchanged.
- Auto-upgraded to v2 in memory on first load.
- "Export Critters" on the Critters tab lets a user bulk-export their v1 collection as v2 `.critter` files (one click, writes to Downloads).

## 10. Technical architecture changes

Keep changes minimal. The goal is to enable Pillars A–D, not to redesign the engine.

### New modules

- `src/rarity.py` — tier enum, distribution roll, per-tier modifier dataclass.
- `src/auras.py` — 4 small aura render functions called from Animal base draw.

- `spawn_manager.py` — rolls a rarity tier per spawn; removes hardcoded golden-kitten / unicorn special cases.

- `animals_custom.py` — same aura hook; reads `rarity_strategy` from meta.
- `config.py` — adds `rarity` block, `first_run_completed` flag, `seen_log` (optional).
- `settings_window.py` — IA overhaul to 4 tabs; sv-ttk integration; import preview modal; export button; drag-drop hook.
- `storage.py` — `schema_version` migration helper.
- `import_pipeline.py` — preview-before-commit path; alternative bg removal fallback.
- `overlay.py` — SDL file-drop event handler routes to `sharing.import_critter_package()`.

### Config migration

- v1 → v2: deep merge with new `DEFAULT_CONFIG` adds rarity block and `first_run_completed: false` (so existing users see the welcome once). All existing keys preserved.
- No version field needed; the deep-merge pattern continues to work.

### Build/release changes

- `release.ps1` unchanged. The pipeline is good.
- `requirements.txt` adds: `sv-ttk`. That's the only new dependency.
- `CritterOverlay.spec`: add `sv_ttk` to hidden imports / datas if PyInstaller doesn't auto-detect the .tcl files. Verify with a clean build before tagging.
- `installer/installer.iss`: no changes expected. Confirm installed file list still matches.
- Confirm bundle size delta after sv-ttk is added; budget is <2 MB increase.

### What we are *not* doing

- No ECS rewrite.
- No event bus framework — just a 30-line dispatcher for the unsafe cross-thread paths.
- No spatial hash for collisions (current O(n²) handles current spawn caps).
- No immutable config snapshots (the deep-merge + read-mostly access pattern is fine).
- No animals.py split into Animator/Renderer/Physics. Tempting, but out of scope.

## 13. Risks and decisions needed

### Decisions (all resolved 2026-05-23 — see §0)

All five decisions are resolved. Summary in §0. Do not re-litigate.

### Risky ideas that sound cool but should not ship in v2.0

- **Online critter gallery.** Killing this in §14.
- **ECS rewrite of `animals.py`.** Tempting, scope-creep death.
- **PySide6 migration.** Discussed and rejected.
- **AI-generated critters from text prompts.** Requires a model dependency (huge) or a cloud call (violates non-negotiables).
- **Multi-monitor critter routing.** Sounds fun, full of platform footguns. Defer.
- **Custom critter physics overrides** (e.g. flying, bouncing). Defer until rarity ships and stabilises.

### Dependency risks

- `sv-ttk` adds ~500KB of .tcl assets to the PyInstaller bundle. Verify the `.spec` file picks them up via hidden imports or `datas`. Acceptable.
- No other new dependencies in this plan. Every added package widens the PyInstaller bundle (and the `.exe` download size), so hold the line.
- The legacy `__main__.py` zipapp bootstrap is no longer the shipping path. Consider deleting it in Phase 5 to avoid future confusion — but only after confirming no script or doc still references it.

### Compatibility risks

- Old config files with `golden_kitten` or `unicorn` keys: Phase 2 must keep them readable even if the spawn logic changes. Deep-merge handles unknown keys; legacy keys can sit idle.
- Old `meta.json` without `schema_version`: handled by Phase 1 migration helper.
- `.pyzw` install on Windows 10 vs 11: test both before tagging.

## 14. Explicit non-goals for v2.0

Rejected outright. Do not implement these even if a user asks.

- **Accounts.** No login, no profile, no auth of any kind.
- **Cloud sync.** Settings and custom critters stay in `%APPDATA%`. No "sync your critters to all your devices."
- **Online critter marketplace or gallery.** Not in v2.0, not in v3.0. Sharing is file-based.
- **Multiplayer.** No shared critters across users in real time.
- **Telemetry.** No usage stats, no error reporting, no analytics calls. The only network request is the GitHub update checker (already in v1).
- **Mobile / macOS / Linux.** Windows-first stays Windows-only in v2.0.
- **AI image generation built in.** Would require a model dependency or cloud call. Both violate non-negotiables.
- **Achievements, levels, currency, daily quests, streaks.** Discussed at length in §6.
- **Built-in image editor for custom critters.** Preview-before-commit yes, crop tool no.
- **Notifications / toasts.** Nothing pops up on the user's screen except the first-run welcome and the import confirm dialog.
- **A heavyweight GUI framework migration.** Discussed in §8.
- **Custom critter scripting / behaviour DSL.** Out of scope. Personality is configured by sliders, not scripts.
- **Global screen tint / overlay colour shift.** Permanently rejected. The app is a transparent overlay; tinting breaks that contract and risks chroma-key interactions. Day/night mood is expressed through behaviour only.

### Forward direction (post-v2.0, not part of v2.0 scope)

These are not for v2.0 but worth noting so v2.0 design choices don't accidentally close the door:

- **Cosmetic outfits and accessories for critters** — hats, scarves, collars, seasonal items. Renders as a layer on top of the sprite at a defined anchor point. A natural future surface for both free unlocks and a small one-off paid cosmetic pack later. Implications for v2.0: when the locomotion profile system lands, include a per-frame "anchor point" field (head, back) in the sprite metadata even if nothing uses it yet — cheap to add now, expensive to retrofit. No outfit *content* in v2.0.
- **Seasonal critter packs** — Halloween, winter, etc. as downloadable `.critter` bundles. The `.critter` format from Pillar B already supports this; no extra design needed.
- **A small in-app shop for cosmetics** — possible monetisation lane. Would require a payment integration and one-time license keys (no accounts, no cloud sync — local activation only). Significant non-negotiable implications; revisit only when there's a real cosmetic catalogue to sell.

## 15. Suggested final v2.0 scope

### Must-have
- Species-specific locomotion profiles for all 8 built-in species (Pillar 0).
- Behaviour catalogue with ≥40 named entries (solo idles + pair interactions) (Pillar 0).
- Day/night tint + activity cycle with 6 buckets (Pillar 0).
- Behaviour-tab UI controls (off-switches, intensity, frequency) (Pillar 0).
- Custom critter `locomotion` field in `meta.json` with picker in UI (Pillar 0).
- Rarity tier system with 5 tiers, configurable distribution, visual auras (Pillar A).
- `.critter` export/import format with validation, drag-and-drop, schema-versioned `meta.json` (Pillar B).
- Settings IA overhaul (6 → 4 tabs), inline custom critter controls, renamed labels, tooltips (Pillar C).
- First-run welcome modal (Pillar C).
- `sv-ttk` themed widgets for buttons / sliders / combobox (Pillar C).
- Preview-before-commit on custom critter import (Pillar D).
- Schema migration for v1 `meta.json` (Pillar E).

### Should-have
- Species-pair-specific interactions (kitten+rabbit near-miss, otter+duck splash, etc.) — beyond the generic pair behaviours (Pillar 0).
- Cluster (3+ critter gathering) and edge behaviours (shy-peek, hesitate-at-edge) (Pillar 0).
- Rare-hour and first-spawn-of-day events (Pillar A).
- Per-species rarity min/max (Pillar A).
- Custom critter `rarity_strategy` field (Pillar A + B).
- Alternative bg-removal fallback button (Pillar D).
- Edge feathering on alpha threshold (Pillar D).
- Bulk "Export all critters" action (Pillar B).
- Unified Audio tab with per-critter preview button (Pillar C).
- EXIF stripping on imported source images (Pillar D).
- Event dispatcher for cross-thread calls (Pillar E).
- Update README and write release notes (Phase 5).

### Could-have
- Optional `seen_log` viewable from System tab (Pillar A).
- Colour-blind redundant icons on toggle states (Pillar C).
- Spawn-frequency slider with labelled stops (Pillar C).
- Rarity strategy `common_only` opt-out (Pillar A).

### Defer to v2.1 or later
- Persistent cross-session relationships ("Kitty and Ducky are friends from yesterday").
- Environmental objects (flowers, leaves, yarn ball — Direction C from the original brief).
- Weather effects driven by system context.
- Spatial hash for collisions (only matters above ~50 simultaneous critters).
- Split of `animals.py` into Animator/Renderer/Physics.
- Custom hotkey remapping.
- Manual crop / rotation in import flow.
- Per-critter custom behaviour states beyond personality sliders.
- Multi-monitor critter spawning rules.
- Weather/system-context-driven spawn pools (interesting but adds platform surface).
- ttk dark-theme refinement beyond `sv-ttk` defaults.

### Decisive scope cut
If the schedule slips, cut in this order, hardest first to lose:
1. Species-pair-specific interactions (ship generic pair behaviours only — the 9 species-pair entries become v2.1).
2. Cluster (3+) and edge behaviours.
3. Rare-hour and first-spawn-of-day (drop to v2.1).
4. Bulk export.
5. Alternative bg-removal fallback (ship plain corner flood-fill with a clearer error message).
6. `sv-ttk` integration (ship with raw tk; defer visual polish).
7. Preview-before-commit (ship the v1 import flow with better error messages).

**Do not cut, even under time pressure:** species locomotion profiles, the generic solo/pair behaviour catalogue, day/night cycle, rarity tiers, `.critter` format, settings IA overhaul, schema migration. Those seven are what makes this v2.0 rather than v1.11.
