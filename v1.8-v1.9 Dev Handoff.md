# Critter Overlay: v1.8 shipped / v1.9 scope

---

## What shipped in v1.8

Merged to `main` on 2026-05-18. Branch: `feature/custom-critters`.

### Core feature: offline custom critters

Users import any PNG, JPG, or animated GIF via Settings → Custom → Create.

**Import pipeline** (`src/custom_critters/`):
- `import_pipeline.py` — validation, routing by file type, common pipeline (crop → fit → animate → mask → palette → write)
- `bg_removal.py` — corner-sample flood-fill for opaque images (works well for solid-colour backgrounds; fails for gradients/photos)
- `procedural.py` — split-image walk-cycle generator: whole body bobs ±4px and leans ±5°; bottom half (below 58% height) gets a horizontal shear growing toward the feet (STRIDE_K=0.20, ~±8px at foot edge), blended with a power-curve gradient for a seamless join. 4-frame cycle using numpy + PIL AFFINE transform.
- `masks.py` — per-pixel alpha mask, dilated 2px, stored as `.npy`
- `palette.py` — dominant-colour extraction (Pillow quantise, filter near-grey)
- `storage.py` — slug-hash folder IDs, meta.json I/O, folder scaffolding
- `registry.py` — runtime singleton; pre-loads pygame Surfaces + numpy masks at startup; alpha threshold (< 180 → 0) applied at surface load to kill chroma-key purple fringe

**Runtime** (`src/`):
- `animals_custom.py` — `CustomAnimal(Animal)`: overrides `draw`, `hit_test`, `emit_trail`; inherits all physics (walk, idle, drag, throw, pop, sound)
- `spawn_manager.py` — extended spawn pool includes registry entries; custom critters spawn alongside built-ins
- `sounds.py` — `register_custom(id, profile, seed)` perturbs synthesis params ±5–10% deterministically via `random.Random(seed)`
- `overlay.py` — `spawn_custom(critter_id)` for the Test button; registry wired through
- `main.py` — registry created pre-overlay, reloaded post-pygame-init; custom sound registration on startup and on every config save

### Settings window overhaul

- Custom tab: import dialog (file picker → progress → frame preview → accept), card list, delete with confirmation, Test spawn button
- Animated 96×96 previews on Animals and Audio tabs (pygame → PIL → base64 → ImageTk, rendered via `preview_renderer.py` after pygame.init)

### Bug fixes (originally v1.7 regressions, documented in v1.8)

| Bug | Fix |
|---|---|
| Scroll overscroll past top of page | `after_idle` deferred scrollregion update; `yview_moveto(0)` on first configure |
| Animals page showed only Kitten | `_load_animal_frames()` moved from `__init__` to `_run()` — PhotoImage requires live `tk.Tk` root |
| Animated previews clipped at edges | 2× render canvas + `ImageChops.difference` auto-crop in `preview_renderer.py` |
| Scroll stuck on page switch | Explicit `unbind_all("<MouseWheel>")` in `_show_page`; immediate bind in `_scrollable` |

### Bug fixes in v1.8 itself

| Bug | Fix |
|---|---|
| PNG with mode=RGBA but solid opaque background not bg-removed | Check transparent pixel fraction after convert; fall through to flood-fill if < 1% transparent |
| Purple fringe on transparent-PNG imports | Alpha threshold (< 180 → 0) in `registry._load_frames` via `pygame.surfarray` + baked into stored frames in `_crop_and_fit` |

## Known open issues / v1.9 candidates

### Animation quality (priority: medium)

The split-image stride works but looks generic — the shear creates a convincing stride for sprites with visible legs, but reads as a wobble on blobs or complex shapes. The fundamental limitation is that we're animating from a single static image with no knowledge of limb locations.

**Needs a brainstorm before v1.9 implementation.** Options discussed:

| Option | Effort | Quality | Notes |
|---|---|---|---|
| A: More aggressive transforms | 1 hour | Low | Already at B so marginal gain |
| B: Split-image stride (shipped) | Done | Medium | Functional but generic |
| C: Accept and improve in v1.9 | — | — | Where we are now |
| D: rembg ML background removal | High | High for bg, not animation | Adds 100+ MB to installer |
| E: GIF-first workflow | Medium | High for GIF sources | Only helps users with pre-animated sources |
| F: Skeletal detection + articulation | Very high | High | Probably not worth it for a desktop toy |

Recommendation: brainstorm what a v1.9 "better animation" actually means before starting. May be as simple as exposing GIF import more prominently and accepting that PNG imports will always look approximate.

### Other v1.9 candidates

- Background removal for non-uniform backgrounds (rembg or smart matting) — main failure case is photos
- Trail style picker per critter (palette already extracted and stored, just needs UI)
- Movement personality presets (parameters already exist in Animal, just need per-critter config)
- Custom critter sharing (export/import zip of the critter folder)
- Drawing canvas (pygame surface, basic brush/eraser/fill — defer until there's actual demand)
- Code signing (SmartScreen friction — only matters if distributing more widely)

## Technical debt / things to know

- `animals_custom.py` inherits `Animal` without refactoring the base class. This is intentional (v1.8 scope). If more custom animal types are added in v1.9 it may be worth extracting a shared base.
- `_scaled_cache` in `CustomAnimal` leaks entries when size or opacity changes (old keys stay). Small in practice but not ideal. `clear_cache()` exists for explicit invalidation.
- The flood-fill bg removal is BFS on PIL pixels — slow for large images, but images are validated to < 2048px and the result is stored, so it's a one-time cost.
- Custom critter `source.png` / `source.gif` is stored but never used at runtime. Intended for future re-generation of frames if the procedural pipeline improves without requiring re-upload.
- `Sprite Images/` contains uncommitted changes (turtle/duck sprite sheet filename renames + new frame PNGs). These are unrelated to v1.8 and need a separate commit/branch when that work is continued.
