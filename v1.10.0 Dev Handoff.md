# Critter Overlay: v1.10.0 scope

Builds on v1.9's per-critter personality system by extending it to built-in animals, fixes custom critter trails (currently silently disabled), expands trail and sound palettes, and overhauls custom critter audio.

---

## Features

### 1. Personality sliders for built-in animals

**What:** Speed, idle rate, and trail style controls for each built-in species, inline in the Animals tab — bringing them to full parity with the custom critter gear panel.

**Implementation:**

- **Config:** add `speed_multiplier` (default 1.0) and `idle_rate` (default 0.018) and `trail_style` (default `"none"`) to each species entry in `config.py`'s `DEFAULT_CONFIG["animals"]`. These merge forward-compatibly with existing configs.
- **animals.py:** each built-in `Animal` subclass already reads `BASE_SPEED` and has a hardcoded `IDLE_RATE` class attribute. In `overlay.py` or `spawn_manager.py` where animals are instantiated, apply the per-species multiplier from config after construction: `animal.SPEED *= cfg["speed_multiplier"]` and `animal.IDLE_RATE = cfg["idle_rate"]`. Trail already works per-class; read `trail_style` from config and set the appropriate class flag on the instance.
- **settings_window.py `_page_animals()`:** expand each species row (already has enable checkbox + weight slider) to include the same labeled-slider widget used in the custom critter gear panel. Reuse `_labeled_slider()` helper so the UI is identical.
- No new disk schema needed beyond config.

**Callout:** the existing `_labeled_slider` widget in `settings_window.py` (built for the custom gear panel) should be extracted into a shared helper method before this work starts, so both tabs use the same code path.

### 2. Custom critters in the Audio tab

**What:** custom critters appear in the Audio tab with a checkbox to enable/disable their pop sound — same pattern as built-in species.

**Implementation:**

- `_page_audio()` currently iterates `SPECIES` (the 8 built-ins). Add a second section below the built-ins: "Custom critters", populated from `self._registry.all()`.
- Sound on/off is already stored per-critter in `config["custom_animals"][critter_id]` as `sound` (bool). The checkbox reads/writes that key via the existing `_set()` helper.
- If a custom critter has no sound assignment yet, it defaults to the first preset (see feature 3).
- The section should be hidden (or show a placeholder) when no custom critters are imported.

---

### 3. Fix custom critter trail emission (bug)

**What:** the trail style selector exists in the UI and saves to meta.json correctly, but trails never appear. Custom critters silently emit nothing regardless of the setting.

**Root cause:** `CustomAnimal.emit_trail()` at `animals_custom.py:145-146` is overridden to `return []` unconditionally. This was a deliberate v1.8 lock ("trails reserved for rare built-ins") that was never removed when the trail UI shipped in v1.9. The flag wiring in lines 63-70 is correct — `LEAVES_TRAIL`, `TRAIL_PALETTE`, `TRAIL_RATE`, and `TRAIL_STAR` are all set properly when `trail_style != "none"`.

**Fix:** delete the `emit_trail()` override entirely. The parent `Animal.emit_trail()` respects all those flags and will work correctly.

### 4. Expanded trail styles for custom critters

**What:** more trail style options beyond "none / dots / stars", selectable from the gear panel.

**Proposed new styles:**

| Style | Character | Implementation |
|---|---|---|
| `sparkles` | Small 4-point stars, fast fade, high rate | `TRAIL_STAR=True`, rate=25, size=4, life=0.5 |
| `bubbles` | Larger hollow circles, slow drift upward, slow fade | New draw mode: stroke-only circle; `vy` offset on spawn |
| `glitter` | Tiny dots, very high rate, very short life | `TRAIL_STAR=False`, rate=40, size=2, life=0.25 |
| `hearts` | Small heart shapes | New draw mode in `TrailParticle` |

**Implementation:**

- `trail_style` in meta.json is already a freeform string — new values are backward-compatible (unknown values fall back to "dots").
- `TrailParticle` needs two new draw modes: hollow circle (bubbles) and heart (hearts). Add a `style` parameter to `TrailParticle.__init__()` alongside the existing `star` bool, then branch in `draw()`.
- Bubble particles need a small upward velocity component (`vy = -15 px/s`) added to `TrailParticle` and applied in `update()`.
- The gear panel trail radio buttons expand from 3 options to 6.
- Apply the same expanded options to built-in animals via the Animals tab sliders (feature #1) once this is done.

### 6. Expanded preset sounds + sound file upload for custom critters

**What:** more preset sound profiles selectable per custom critter, plus the ability to upload a `.wav` or `.mp3` file as a critter's sound.

#### 6a. More preset sounds

Current presets are the 8 species sounds (kitten, turtle, … panda). Add a palette of ~6 additional short synthesised sounds in `sounds.py` covering common cute categories:

| Profile name | Character |
|---|---|
| `squeak` | High-pitched quick squeak |
| `chirp` | Bird-like short trill |
| `bloop` | Soft water drop |
| `pop` | Light cartoon pop |
| `grunt` | Low short grunt |
| `bell` | Soft chime |

Each added to `GENERATORS` dict; `scripts/build_sounds.py` regenerates the WAVs automatically. The UI sound picker (custom critter gear panel) lists all available profiles by name.

#### 6b. Sound file upload

- **meta.json field:** add `sound_file: ""` (empty = use profile). When non-empty, this is an absolute path to a user-supplied audio file; takes priority over `sound_profile`.
- **Import:** add a "Upload sound" button in the custom critter gear panel. File picker filters to `*.wav;*.mp3`. On selection:
  - Copy the file into the critter's data directory as `sound.wav` (convert mp3 → wav via `pygame.mixer` on load, or use a one-time conversion step at import time using `pydub` if available, else reject .mp3 with a clear message). **Simplest approach:** at import time, load the file with `pygame.mixer.Sound(path)` — this handles WAV natively and MP3 via SDL_mixer on most systems. If it fails, show an error and don't update meta.
  - Store the copied path in `sound_file`.
- **SoundManager:** in `sounds.py`, when `sound_file` is set, load from that path instead of synthesising from the profile.
- **UI:** show the filename (not full path) next to the upload button when a file is loaded; provide a "✕ Remove" to revert to profile.

**Dependency note:** `.mp3` support via `pygame.mixer.Sound` depends on SDL_mixer being built with MP3 support — which it is in the bundled SDL2_mixer.dll. No new Python dependency needed. Test on the bundle before releasing.

### 7. Sound preview button

**What:** a small ▶ button next to each sound option (preset profiles and uploaded file) that plays a short preview without saving the selection.

**Implementation:**

- In the custom critter gear panel sound picker, add a ▶ button per row.
- On click: call `SoundManager.play_preview(profile_or_path)` — a new method that plays the sound once at current volume. Non-blocking (fire and forget via `pygame.mixer.Sound.play()`).
- One preview plays at a time: stop any in-progress preview before starting the next.

### 8. Per-critter size slider for custom critters

**What:** a size slider in the custom critter gear panel (same collapsible section as speed/idle/trail). Controls the rendered size of the critter on screen.

**Implementation:**

- **meta.json field:** add `size_multiplier: 1.0` (range 0.5 – 3.0). Default 1.0 = current behaviour.
- **animals_custom.py `CustomAnimal`:** `self.size = int(BASE_SIZE * meta.get("size_multiplier", 1.0))`. The `_scale_cache` already keys on `(idx, size, flip)` so this slots in cleanly.
- **UI:** labeled slider (tiny / small / normal / large / huge) mapping to `[0.5, 0.75, 1.0, 1.5, 2.5]` — same 5-stop pattern as the speed slider. Lives at the top of the gear panel.

### 9. Inline rename for custom critters

**What:** the critter name in the card list should be directly editable (click to edit in place) rather than requiring a separate flow.

**Implementation:**

- Replace the name `Label` in `_custom_critter_row()` with a `ttk.Entry` that renders as a label until focused (use `state="readonly"` → `"normal"` on click).
- On focus-out or Return: validate (non-empty, ≤ 32 chars), call `write_meta()` with the updated name, refresh the card label.
- If invalid, revert to the previous value.

### 10. Catchable thrown critters

**What:** a critter in `THROWN` state can be caught mid-flight by clicking or dragging it again. This cancels the throw and puts the critter into `DRAGGING` state, giving the player fine control rather than watching it sail off screen.

**Implementation:**

- `overlay.py` hit-testing already iterates animals on mouse-down. Thrown critters are currently excluded from drag pickup — remove that exclusion so `THROWN` animals are valid grab targets.
- On successful grab: transition state from `THROWN` → `DRAGGING`, zero the velocity, proceed with the normal drag flow.
- No new state needed — this is a one-line guard removal plus confirming the hit-test works at thrown speeds (it uses the mask, which is fine).

---

### 11. Thrown critters that lose momentum stay on screen

**What:** currently a thrown critter in `THROWN` state always drifts off screen regardless of what happens to it. If a collision reduces its speed below a threshold, it should transition to `SCATTERED` (then back to `WALKING`) rather than continuing its exit trajectory.

**Implementation:**

- In `overlay._resolve_collisions()`, after applying velocity exchange to a `THROWN` animal, check its resulting speed.
- If speed drops below the `SCATTERED` entry threshold (currently 80 px/s — the same check used for hit animals), transition it to `SCATTERED` state and let the existing scatter timer take over.
- `SCATTERED` already handles deceleration, wall bouncing, and the return to `WALKING` — no new logic needed there.
- The feel: throw a critter at a wall of others, it either punches through (still fast) or gets absorbed (momentum-robbed → scatter → resume normal life).

## Known risks

- **MP3 on the bundle:** `pygame.mixer.Sound` MP3 support depends on SDL_mixer's MP3 backend. Test with a real `.mp3` on the installed bundle before releasing -- not just from source.
- **`_scale_cache` leak (carry-over from v1.9):** adding a size slider makes this more likely to bite. Wire `clear_cache()` to the size slider's on-change handler at the same time as implementing #5.
- **Settings window height:** adding sliders to every species row in the Animals tab will make the tab taller. Check the minimum window size and add scrolling to the Animals tab if needed (the Custom tab already scrolls).

## Post-v1.10.0 backlog

Carried over from the v1.9 handoff. Not in v1.10.0 scope but should not be lost.

### Critter sharing
Export/import a custom critter as a self-contained zip. Storage layout is already one folder per critter so zip I/O is straightforward -- single new dialog, no schema changes needed.

### Frames-dialog animated preview
The import-from-frames dialog shows static thumbnails. A live animated cycle preview before committing to import is low effort -- reuse the `_start_anim_on` hover pattern already used in the card list.

### Re-generation from source
`source.png` / `source_frames/` are stored per critter but never used after import. If the procedural pipeline improves, a "re-generate animation" button per critter would let users get better animations from their existing imports without re-importing.

### Perimeter-walker collision
Perimeter walkers are deliberately excluded from collision (v1.9 decision -- keeping them on their path during a scatter is non-trivial). Satisfying fix: a scatter impulse that temporarily suspends perimeter mode and resumes it after the scatter timer expires.

### Code signing
SmartScreen shows a warning on unsigned executables from unknown publishers. Only matters for wider distribution, but worth revisiting if the app gets shared more broadly.

## Technical debt to know

- `animals_custom.py` inherits `Animal` without refactoring the base class. Fine for now; extract a shared base if more custom animal types are added.
- `settings_window.py` is large (~1400 lines). No structural issues but consider splitting the Custom tab methods into a mixin if it grows further.
- The flood-fill background removal is BFS on PIL pixels -- slow for large images but a one-time cost at import (result stored). Still the right call unless `rembg` is adopted.
