# Critter Overlay: v1.9 shipped / v2.0 scope

---

## What shipped in v1.9

Committed to `main` on 2026-05-23.

### Elastic critter collision

All animals participate in 2-D equal-mass elastic collisions resolved in `overlay._resolve_collisions()` — called once per frame after all position updates, before the reap pass.

**Physics:** For each overlapping pair, velocity components along the collision axis are swapped (billiard-ball model). Perimeter walkers and dragged animals are excluded. A post-collision speed threshold (80 px/s) determines whether the hit animal enters `SCATTERED` state or just gets a gentle redirect.

**`SCATTERED` state** (new in `animals.py`): animal coasts freely with 2.0 px/s² drag, bounces off walls, and transitions back to `WALKING` when the 1.2s timer expires or speed drops below 35% of `BASE_SPEED`. Minimum scatter speed clamped to 130 px/s so low-energy hits still look punchy.

Thrown critters transfer momentum on impact and stay in `THROWN` state (drift out of screen naturally). Result: throw one critter at a group → bowling-pin scatter.

### Per-critter personality sliders

New `meta.json` fields (backward-compatible defaults applied to all existing critters):

| Field | Type | Default | Range |
|---|---|---|---|
| `speed_multiplier` | float | 1.0 | 0.10 – 12.0 |
| `idle_rate` | float | 0.018 | 0.003 – 0.250 |
| `trail_style` | string | "none" | "none" / "dots" / "stars" |

`speed_multiplier` is applied to `BASE_SPEED = 50` before `super().__init__()` so initial velocity is correct. `idle_rate` replaces the hardcoded `0.018` in `Animal._update()` — now `self.IDLE_RATE` (class attribute on `Animal`, overridden per-instance in `CustomAnimal`).

Speed labels: snail (0.10×) → slow (0.30×) → average (1.0×) → fast (2.5×) → rapid (5.0×) → supersonic (12.0×).
Idle labels: wired (0.003) → active (0.008) → normal (0.018) → lazy (0.045) → sleepy (0.100) → narcoleptic (0.250).

Trail uses the critter's extracted `trail_palette` (already stored in v1.8 meta.json). Dots: rate=15, size=6. Stars: same rate, `TRAIL_STAR=True`.

### Frame-strip import

New `run_import_frames(paths, name, custom_dir)` entry point in `import_pipeline.py`. Accepts 2–8 PNG paths in walk-cycle order.

Per-frame: validates file, checks transparency (>1% transparent pixels = already transparent, skip bg removal), else runs `remove_background`. Global bbox alignment across all frames (same as GIF path). Saves originals to `source_frames/` for future re-generation. Sets `import_method = "frame_strip"`, `procedural_animation = False`.

### Settings UI overhaul (Custom tab)

- Two import buttons: "Import critter" (existing single-image path) and "Import from frames" (new).
- **Frames dialog**: multi-select or add-one-at-a-time, horizontal scrollable strip, ←/→/✕ per frame, live transparency badge (✓ transparent / ⚠ bg-remove), name autofill from first filename.
- **Card list**: 96×96 hover-animated preview (PIL frames loaded lazily on first hover, cancelled on leave), frame count + method badge, gear button → inline collapsible settings panel with speed/idle sliders and trail radio buttons.
- Shared `_finish_import()` helper used by both import dialogs.

## Known open issues / v2.0 candidates

### Custom critter UX
- **Critter sharing** (export/import zip) — deferred from v1.9. Storage layout already self-contained so zip is straightforward.
- **Frame preview in frames dialog** — the dialog shows static thumbnails but no animated cycle preview before import. Low effort to add (same hover-anim pattern already used in cards).
- **Re-generation from source** — `source.png` / `source_frames/` are stored but never used. If the procedural pipeline improves, could offer a "re-generate animation" button per critter.

### Physics
- **Perimeter walkers excluded from collision** — deliberate for v1.9 (keeping them on their path is complex). Could be revisited: a scatter impulse that temporarily suspends perimeter mode and resumes it after the scatter timer would be satisfying.
- **Thrown critter doesn't rebound** — after hitting a group it loses speed but stays `THROWN` and drifts off screen. A "bounce back onto screen" mode could feel better.

### Other candidates
- **Trail style for built-in animals** — currently only the two rares (otter, panda) have trails. Trail config is already per-class; exposing a UI toggle for all species is a small change.
- **Movement personality for built-in animals** — `IDLE_RATE` is now a class attribute; a settings slider for built-ins would be consistent.
- **Code signing** — SmartScreen friction on `.pyzw`. Only matters for wider distribution.
- **`_scale_cache` leak in `CustomAnimal`** — old (idx, size, flip) entries stay when size changes. `clear_cache()` exists; wiring it to the size slider would fix it cleanly.

## Technical debt to know

- `animals_custom.py` inherits `Animal` without refactoring the base class. If more custom animal types are added, extracting a shared base is worth doing then.
- `settings_window.py` is large (~1400 lines). No structural issues but further features should be added carefully; consider splitting the custom tab methods into a mixin if it grows further.
- The flood-fill bg removal is BFS on PIL pixels — slow for large images but a one-time cost (result stored). Still the right call unless rembg is adopted.
